# 写作沙盒 · 昔涟

✍️ **AstrBot 委托式独立写作沙盒** —— 对昔涟说一句「写一段……」，她就在后台为你分节写作，自动保存成 txt，写完告诉你。你只负责描述「想要什么效果」，剩下的交给她。

不需要记任何指令前缀，用自然语言说话就行。

## ✨ 特色

- **自然语言吩咐**：不用学命令，「写一段她推门进来，雨还没干」就是全部操作方式
- **独立沙盒**：写作上下文和主聊天完全隔离，聊着天写作互不打扰
- **后台分节生成**：长文自动拆成每节约 2000 字（可在插件配置调整）的小节逐节后台写，你可以先干别的
- **风格卡学习**：丢几篇素材进去，提炼成「风格卡」，以后都按这个味道写
- **长篇连载工作区**：大纲、设定书、章节摘要自动维护，写不跑偏
- **产出自动落盘**：每段文字保存为 txt，回复里给摘要和路径，随时可取
- **大纲分批编写不超时**：章节多的大纲自动分批提交，不再卡在一次性输出上
- **中断可续写**：写作中途重启也不怕，说「继续上次写作」就从断点接着写，已写内容都在
- **完稿自动深层清洗**：分节标题等残留会被自动扫掉，不再混进正文里

## 🚀 快速开始

1. 把插件文件夹放进 AstrBot 的 `data/plugins/`，重启或热加载
2. 直接对昔涟说：

```
写一段她推门进来，雨还没干
```

她会在后台生成文字、保存成 txt，然后告诉你写好了。

## 🎮 怎么用（说人话就行）

| 你只要说 | 沙盒会做什么 |
| --- | --- |
| 写一段…… / 续写 / 改写上一段 | 按当前风格卡 + 约束生成文字，落盘 txt，写完推送 |
| 这段太短 / 太长 / 换第一人称 / 节奏快一点 | 调整对应约束项，下次生成立即生效 |
| 这段好，收藏 | 存为高权重样本，以后风格学习优先参考 |
| 学一下这些素材的风格 | 从素材库提炼风格卡，之后都按这个味道写 |
| 写《XX》第 3 章 | 进入长篇模式，自动维护章节摘要和设定书 |
| 给《XX》定个大纲 | 规划全局脉络 + 分章节点，写作时自动注入；章节多时自动分批提交 |
| 给配角也设个卡 | 生成统一格式人设卡，写正文时按出场角色自动注入 |
| 同一角色有两张卡 → 说「把 A 并进 B」 | 合并重复卡：别名吸收、空位互补、大纲出场名单同步替换（sandbox_character merge） |
| 人设卡残留剧情安排？ | 写正文时自动只注入人物素材（秘密/剧情字段/关系备注不进正文上下文），完稿还会扫作者视角残留 |
| 看看沙盒现在是什么设置 | 查看当前风格卡与约束 |
| 写到哪了 / 后台好了吗 | 查看后台写作进度 |
| 写到一半重启了，说继续上次写作 | 从断点继续，已写内容保留 |
| 清洗旧稿 | 扫掉章节文件里的分节标题等残留（sandbox_cleanup scrub） |
| 清空沙盒 | 重置沙盒历史（可连约束、风格卡一起清） |

## 🧠 它怎么工作（了解一下更好用）

- 每次生成 = 系统提示词 + 风格卡 + 约束 + 沙盒历史 + 你这次的指令
- 沙盒历史独立保存，写长文时不会和日常聊天串味
- 长文自动分节后台生成，中途随时可问进度
- LLM 调用改为流式 + 空闲超时：慢而正常的生成不再被误杀，失败会报出超时/限流/上下文超限等真实原因
- 写作任务每节落盘（jobs.json），重启后可恢复
- 产出保存在 `outputs/` 目录，按时间命名

## ⚙️ 引擎配置

在 AstrBot WebUI 的插件配置页可以调这几个引擎参数，不用动代码：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| section_target_chars | 2000 | 每节目标字数（单次生成越短，超时概率越低） |
| max_sections | 30 | 单次任务最多分成多少节 |
| section_retry | 2 | 单节生成失败的额外重试次数 |
| stream_first | true | 优先流式调用；设为 false 可整体回退旧的非流式模式 |
| stream_idle_timeout | 60 | 流式空闲超时秒数（连续这么久没有新内容才判死） |
| llm_total_timeout | 300 | 单次 LLM 调用总超时上限（秒） |

关于续跑范围的小说明：短篇（没带作品名）恢复时只接回最后一节所在的那份文件；完整的断点续跑在长篇模式——断点存在作品草稿里，逐节都能接上♪

## 🎨 风格卡：教「怎么写」，不教「写什么」

风格学习只捕获**笔法维度**，跟剧情和人设彻底解耦：

- 句式结构、词汇偏好、描写侧重与密度
- 人称与视角、节奏快慢、感官侧重
- 尺度与露骨度、比喻方式

**不收录**：语气、题材、具体意象词。这样一张风格卡可以跨题材复用，不会一写某角色就自动带上某篇文的标签。

- 素材放 `library/`（txt / md），收藏的样本自动优先
- 多张风格卡可以**组合**：设一张底卡，再按维度指定来源（比如「句式用 A 卡、尺度用 B 卡」）

## 🎭 人设卡 v2：教「人是谁」，不管「剧情往哪走」

人设卡和剧情彻底分家，卡里只放写正文用得上的「人物素材」：

- **persona 段（v2 新增）**：外貌锚点、示例台词 2~3 句、语言节奏——其中**示例台词是锚定角色腔调最有效的手段**，优先填满
- **canon 与 inferred**：演绎补足（原设定里没有、推出来）的字段登记在 meta.inferred，渲染时标「（演绎）」，设定与推测一眼分清
- **剧情退出人设卡**：人物弧线、剧情钩子归大纲与设定书管，卡里不再存
- **丰富度硬线**：主角卡要求外貌锚点≥3 / 性格≥3 / 示例台词≥2，配角各≥1——缺了 save 时会被打回，并列出缺项

## 🔄 存量卡迁移到 v2

插件升级到 0.4.0 后，老版本（v1）人设卡跑一次迁移脚本就能升级，不用手动改：

```bash
# 第一步：dry-run，只出迁移报告，不动任何卡
python scripts/migrate_v1_v2.py --data-root data/plugin_data/astrbot_plugin_write_sandbox

# 第二步：看完报告、确认没问题后，加 --apply 实际迁移
python scripts/migrate_v1_v2.py --apply --data-root data/plugin_data/astrbot_plugin_write_sandbox
```

- 默认 dry-run 只出报告不落盘，**apply 前先看 dry-run 报告并自行确认**
- apply 时每张源卡自动留一份 `.bak_v1` 备份，随时可回退
- 全局卡的剧情字段（搬不进设定书的）会存进 `migration_dropped.json`，不丢数据，去留由你定

## 📁 目录结构

插件本体（代码）：

```
astrbot_plugin_write_sandbox/
├── main.py            # AstrBot 入口与工具注册
├── handlers/          # 业务逻辑（6 个 Mixin：base / write / outline / character / learn / misc）
├── core/              # 沙盒核心包（analysis / cardops / characters / cleanup / constants / library / llmerrors / outlineops / sandbox / storage / style / textclean / works）
├── prompts.py         # 提示词模板
├── scripts/
│   └── migrate_v1_v2.py  # 存量人设卡 v1→v2 迁移（默认 dry-run 只出报告，--apply 实迁，见「🔄 存量卡迁移到 v2」）
├── tests/
│   └── test_p0.py     # P0 稳定性单测（python tests/test_p0.py 直接跑，无需装依赖）
├── _conf_schema.yaml  # 引擎参数配置（WebUI 插件配置页可见，见上文「⚙️ 引擎配置」）
├── metadata.yaml      # 插件元信息
└── PLAN.md            # 开发方案（需求变更先改这里）
```

运行时数据不放在插件目录，而是在 `data/plugin_data/astrbot_plugin_write_sandbox/<用户ID>/` 下：

```
<用户ID>/
├── outputs/          # 写作产出 txt
├── library/          # 素材库（放入待学习的 txt / md）
├── favorites/        # 收藏的高权重样本
├── style_cards/      # 风格卡库
├── stories/          # 长篇作品工作区（大纲 / 设定书 / 章节摘要）
├── characters/       # 人设卡
├── constraints.json  # 约束表（可手动编辑）
└── jobs.json         # 写作任务断点记录（断点续跑靠它）
```
